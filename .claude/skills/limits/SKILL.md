# /limits — упираемся ли мы в лимиты

Только чтение: ничего не меняем ни в базе, ни в настройках. Никуда не входим с паролем: если сайт просит войти, пишем «не проверено, нужен вход» и идём дальше. Ключи из `web/.env.local` в ответ не выводим.

Отвечаем по-русски: одна таблица, потом «Что сделать» (только по жёлтым и красным строкам), потом «Не удалось проверить».

## 1. База Supabase — один запрос

Supabase MCP `execute_sql`, project `yhgdcdkfkerzuhnzjzrz`, текст из `supabase.sql` рядом с этим файлом (прочитать и отправить целиком). Он отдаёт одну строку JSON:

| Поле | Что смотреть |
|---|---|
| `db.mb`, `db.top` | размер базы и 5 самых больших таблиц. `cron.job_run_details` — история pg_cron, сама не чистится |
| `storage.mb`, `storage.buckets[].mb_7d` | реальный размер файлов сейчас и прирост за 7 дней. **Дней до 1 ГБ = (1024 − mb) / (mb_last_7d / 7)** |
| `connections` | `now` из `max` (60 на бесплатном) |
| `cron_failed_24h` | упавшие фоновые задачи |
| `pg_net` | вызовы cron → catchrange.com за ~6 ч. Таймауты 5 с — это холодный старт Vercel, маршрут всё равно отрабатывает; тревожно только `http_errors` |
| `telegram` | `stuck_over_15m` > 0 или ошибки 429 (флуд-лимит) — плохо; «bot was blocked» — норма |
| `errors_24h` | ошибки приложения и серверных маршрутов (`api:…`) |
| `activity_7d` | для оценки сервисов без своего счётчика (Mapbox, Fishial) |

## 2. Панель Supabase — месячные квоты

Встроенный браузер (`mcp__Claude_Browser__*`): открыть `https://supabase.com/dashboard/org/ixgohfsbludyzhhvbxru/usage`, подождать 4 с и выполнить:

```js
const t = document.body.innerText.split('\n').map(s=>s.trim()).filter(Boolean); const out=[]; t.forEach((s,i)=>{ if (/\s\/\s.*\(\S*%\)$|^\S+ \/ [\d\s]+(MAU)?$|Unavailable in plan/.test(s) && s.length<50) out.push(t[i-1]+' => '+s) }); [t.find(s=>/\d{2} \w{3} \d{4} - /.test(s)), ...out].join('\n')
```

Первая строка — расчётный период (начинается 3-го числа). Прогноз на конец периода = использовано / прошло дней × дней в периоде.

«Storage Size» в панели — среднее за период, оно ниже реального. Для лимита в 1 ГБ берём `storage.mb` из шага 1.

Если исходящего трафика (Egress) за период больше половины, найти, что его съедает. Это MCP `query_logs`, последние 24 ч:

```sql
select multiIf(log_attributes['request.path'] like '/storage/v1/object/%', 'файлы целиком', log_attributes['request.path'] like '/storage/v1/render/%', 'превью', log_attributes['request.path'] like '/rest/%', 'API', 'прочее') as kind,
  log_attributes['response.headers.cf_cache_status'] as cache, count() as reqs,
  round(sum(toUInt64OrZero(log_attributes['response.headers.content_length'])) / 1048576, 1) as mb
from logs where source = 'edge_logs' group by kind, cache order by mb desc
```

У ответов API размер в логах обычно не указан (сжатые ответы). Поэтому считаем через панель, а логи используем только чтобы понять, что больше всего грузится.

## 3. Vercel — панель Usage

MCP-коннектор Vercel на команду `gamag` отвечает 403, поэтому идём через встроенный браузер. Открыть `https://vercel.com/gamag/~/usage` (это последние 30 дней), подождать 4 с и выполнить:

```js
document.querySelector('main').innerText.split('\n').map(s=>s.trim()).filter(Boolean).slice(0, 80).join(' | ')
```

## 4. Сервисы без счётчика — оценка по активности

Берём `activity_7d` из шага 1 и считаем на 30 дней (× 30 / 7):

- **Mapbox, загрузки карты** ≈ `app_open`. Карта монтируется один раз за открытие приложения.
- **Mapbox, растровые тайлы** ≈ `sector_screens` × 9. Это превью сектора, цвет сектора и мини-карта в «Где это?». Браузер их кэширует, так что это потолок.
- **Fishial** ≈ `confirm_screens`. Распознавание вызывается на каждой форме улова. Маршрут `api/recognize-fish` при кончившихся кредитах молча отдаёт пустой список, так что увидеть это можно только по пропавшим подсказкам вида. Отметить как «оценка».
- **Open-Meteo** ≈ `catches` × 3 + прогнозы по cron (~300 в сутки). Сравнить с 10 000 в сутки.

Консоль Mapbox (`console.mapbox.com`) во встроенном браузере не залогинена, туда не входим.

## Светофор

- 🟢 — прогноз на конец периода меньше 50%.
- 🟡 — прогноз 50–80%, или файлы и база заполнятся быстрее чем за 60 дней.
- 🔴 — прогноз больше 80%, или упрёмся раньше конца периода, или файлы и база заполнятся быстрее чем за 21 день.

## Что уже известно (12.10.2026)

- **Фото улова.** С 05.10 были 1920 px / 0.88 (файлы ~700 КБ, +28 МБ в сутки). 16.10 новые стали 1600 px / 0.82 (`CameraScreen.tsx`, `MAX_PHOTO_SIDE` / `JPEG_QUALITY`), старые пережаты `web/scripts/recompress-photos.mjs` (−89 МБ). Дальше ~+14 МБ в сутки; главный кандидат на упор в лимит остаётся (и место, и трафик: карточка улова грузит оригинал). Скрипт безопасно запускать повторно.
- **История cron.** `cron.job_run_details` — больше половины базы (~43 МБ, растёт примерно на 2 500 строк в сутки). Чистить нечем.
- **Логи.** Log Ingestion на 12.10 — 73% от 1 ГБ за 9 дней периода. Пока не применяется, станет лимитом с 2027.
