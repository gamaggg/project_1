# clan-siege-lock-13-11 — общак закрыт на время осады штаба

Просьба владельца 13.11.2026: «пока осада, ты не можешь тратить деньги в магазин и т. д.» и «почему я могу перенести штаб, который в осаде».

- `01_siege_lock.sql` — `_clan_treasury_spend` отказывает `CLAN:siege_lock`, если у клана есть строка в `clan_sieges` (кроме списания добычи `looted` в `clan_hq_tick`). Все траты из общака идут через эту функцию: магазин, постройка, ускорение, «Выход», постановка и перенос штаба.
- `01_siege_lock_ROLLBACK.sql` — прежнее тело (снято с живой базы 13.11, совпадает с `clan-update-06-11/02_buff_hq.sql`).
- `01_siege_lock_DRYRUN.sql` — прогон в одной строке для SQL-редактора; всегда заканчивается ошибкой «DRYRUN (всё откатано)».

Прогон 13.11.2026 (SHA-256 строки совпал с файлом): «клан 39, баланс 1127; 1) без осады трата прошла; 2) в осаде отказ: CLAN:siege_lock; 3) добыча при падении списывается». После прогона: тело функции прежнее, баланс клана 39 — 1127, строк с меткой `dryrun` — 0.

Применять: в тихие часы (20:00–03:00 UTC), после «применяй». В конце записать в журнал миграций (`clan_siege_lock_13_11`). Клиент понимает `siege_lock` (`REASON` в `lib/clan2/live/server.ts`) и сам выключает кнопки, так что код можно выложить раньше миграции.
