# fishing-hex

Соты 600 м по берегу моря и всем водам OpenStreetMap вокруг Батуми.
Прототип для рыбацкой карты: каждая сота, которая касается воды, получает id и тип воды.

## Как запустить

```bash
npm install
npm run all        # fetch_osm.sh -> build_hex.mjs -> assemble.mjs
open map.html
```

Нужны Node 18+ и curl. Python нужен только для необязательного tiles.py.

## Что делает каждый файл

| Файл | Что делает |
|---|---|
| `fetch_osm.sh` | Забирает из Overpass API береговую линию, реки, ручьи, каналы и полигоны воды в bbox. Пишет `osm.json`. |
| `build_hex.mjs` | Строит гексагональную сетку 600 м и оставляет соты, которые пересекают воду. Пишет `hex.geojson` и `water.geojson`. |
| `assemble.mjs` | Собирает `map.html` с Leaflet, соты и вода вшиты в файл. Подложка с tile.openstreetmap.org. |
| `tiles.py` | Необязательно. Скачивает тайлы OSM в `tiles.json`, тогда `assemble.mjs` вшивает их и карта работает офлайн. |

## Что крутить

Всё в начале `build_hex.mjs`:

- `BBOX` район. Тот же bbox надо поменять в `fetch_osm.sh`.
- `WIDTH_M` ширина соты в метрах.
- `PRIORITY` какой тип воды главнее, если сота касается нескольких.
- `RING_AROUND` вокруг каких типов строить второй ряд сот.

## Типы воды

- `sea` береговая линия, `natural=coastline`
- `river` реки: осевые линии `waterway=river` плюс полигоны `natural=water` с `water=river|oxbow|canal` (русла, старицы)
- `stream` ручьи и каналы, `waterway=stream|canal`
- `lake` остальные полигоны `natural=water`: озёра, пруды, водохранилища

Болота (`natural=wetland`) не берутся.

## Если нужны глобальные id сот

Своя сетка даёт id вида `B0123`, они стабильны только при тех же настройках.
Если нужны id, одинаковые во всём мире, берите H3 (пакет `h3-js`): `latLngToCell` для точек
вдоль линий и `polygonToCells` для полигонов. Но у H3 нет шага 600 м, ближайшие уровни
это res 9 (около 350 м поперёк) и res 8 (около 800 м).
