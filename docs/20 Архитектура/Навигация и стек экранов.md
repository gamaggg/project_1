# Навигация и стек экранов

`FishZoneApp.tsx` хранит `stack: StackEntry[]` (не просто `currentScreen: ScreenId`) — каждый переход между «просмотровыми» экранами (`screen-territory`, `screen-user-profile`) добавляет запись в стек через `push()`, кнопка «назад» (`pop()`) снимает верхнюю и восстанавливает предыдущую, включая её параметры (`territoryId`/`userId`), а не просто переключает на какой-то один фиксированный «предыдущий» экран. Переход по вкладке нижней навигации (`navClick`) сбрасывает стек целиком (`resetTo`) — вкладки не участвуют в истории «назад», это разные оси навигации (как в большинстве мобильных приложений: таб-бар не то же самое, что кнопка «назад»).

`StackEntry` — размеченное объединение (`{screen:'screen-territory', territoryId}`, `{screen:'screen-user-profile', userId}` и т.д.), не просто список `ScreenId` — иначе `pop()` не знал бы, какую именно территорию/профиль показать при возврате, если один и тот же тип экрана встречается в стеке дважды подряд с разными id (например: территория A → профиль владельца → территория B из его списка → назад → назад — должно попасть обратно на профиль владельца, а не потерять, какой именно профиль это был).

**Побочный баг, найденный и исправленный по пути** (не то, что просил пользователь напрямую, а следствие корректной реализации стека): раньше `activeTerritoryId` был одним общим полем и для потока фиксации улова (геолокация → камера → подтверждение), и для вручную открытой `TerritoryScreen`. Поскольку нижняя навигация (и кнопка «+») остаётся видна поверх `screen-territory`, нажатие «+» во время просмотра территории A могло молча подменить `activeTerritoryId` найденной по геолокации территорией B, ломая то, что должна была показать кнопка «назад» на экране территории. Разделено на `viewingTerritoryId`/`viewingUserId` (управляются стеком, только для чтения) и `catchTerritoryId` (независимое поле только для потока улова).
