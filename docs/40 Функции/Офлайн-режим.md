# Офлайн-режим (без интернета вообще)

Приложение открывается без сети и показывает то, что телефон сохранил с прошлого раза; улов можно записать без связи. Три слоя:

1. **Файлы приложения — service worker (`public/sw.js`).** Хранит собранные скрипты, стили, шрифты и картинки из `public/` (список — `/_next/static/precache.json`, его пишет `scripts/precache-manifest.mjs` после `next build`; ~120 файлов, ~10 МБ), на каждом запуске обновляет их под новую сборку и выбрасывает старые. Страницу открывает с сервера, а если сети нет или она медленнее 4 секунд — со своей копии. Запоминает плитки карты Mapbox (до 1500) и аватарки/фото из хранилища (до 500). Запросы к данным игры (Supabase, `/api`) не трогает. При включённой «экономии трафика» ничего не скачивает. Включается только в боевой сборке (`ServiceWorkerRegister.tsx`).
2. **Данные игры — `lib/offlineCache.ts`.** Через 2,5 с после изменений основные запросы (сектора, профиль, дневник, уловы, челленджи, виды, баффы, казна, рейтинг, клан и др.; список `PERSISTED`) сохраняются в IndexedDB и при запуске возвращаются в кеш запросов. Копия принадлежит игроку, который был вошедшим, живёт 14 дней, новые данные **добавляются** к старым (запуск без сети не стирает то, до чего не дошёл), при выходе из аккаунта стирается.
3. **Вход без сети — `AuthProvider.tsx`.** Последний вошедший игрок хранится в `localStorage` (`range:lastUser`): без сети (или если сервер входа молчит дольше 5 с) приложение открывается под ним, настоящая проверка идёт сама, когда связь вернётся. Сессию без сети не сбрасывают ни `ensureSession`, ни пустое событие входа.

Плюс: «Улов без сети» (`lib/offlineCatches.ts`) — фото, место и время ждут на телефоне и уходят сами; плашка-тост «Нет сети — показываем сохранённое» / «Сеть снова есть».

**Известное:** на Vercel файл `/_next/static/precache.json` не публикуется (локальная сборка его создаёт, на проде — 404; логи сборки недоступны через MCP, причина не выяснена). Поэтому service worker работает в запасном режиме: сохраняет файлы, которые сама страница загрузила за запуск (она присылает их список при регистрации), плюс то, что догружается по ходу. Приложение подгружает экраны при запуске, так что покрытие широкое, но не гарантированно полное. Чтобы получить полный список — выяснить, почему Vercel не отдаёт файл (например, по логам сборки в панели Vercel), либо отдавать список маршрутом.

## Где работает
- Сайт на главном экране (Safari «На экран Домой», Chrome «Установить приложение») — полностью.
- Telegram: зависит от платформы. Если service worker там недоступен (обычно iPhone), страница с нуля без сети не откроется, но уже открытое приложение при потере связи работает и принимает улов.

## Что без сети недоступно
Живая карта за пределами уже просмотренных плиток, рейтинг и чаты в реальном времени, комментарии, захват с проверкой соперников, магазин, слоты — всё, что решает сервер.

## Если что-то пошло не так (аварийный выключатель)
Подменить `public/sw.js` на файл, который сам себя удаляет, и выложить:
```js
self.addEventListener('install', () => self.skipWaiting())
self.addEventListener('activate', (e) => e.waitUntil((async () => {
  for (const k of await caches.keys()) await caches.delete(k)
  await self.registration.unregister()
  for (const c of await self.clients.matchAll()) c.navigate(c.url)
})()))
```
Телефоны подхватят его при следующем запуске, кеши очистятся, приложение вернётся к обычной работе. Данные игры (IndexedDB `range-cache`) при этом остаются и не мешают.

## Как проверить на компьютере
`NEXT_DIST_DIR=.next-prod npm run build`, затем `NEXT_DIST_DIR=.next-prod npx next start -p 3400`. Встроенный браузер приложения service worker не регистрирует — проверять в настоящем Chrome; в `sw.js` есть тестовая команда `{type: 'simulate-offline', on: true}` (притвориться, что сети нет). Логику service worker проверяет скрипт в сессионной папке (`sw-test.mjs`, 12 сценариев).
