# Защита входа и регистрации (капча)

На экранах входа, регистрации, «Забыли пароль» и ввода кода из письма над кнопкой стоит небольшая проверка Cloudflare Turnstile («Подтвердите, что вы человек» / «Успешно»). Пока она не пройдена, кнопка («Войти», «Далее», «Отправить код», «Отправить ещё раз») неактивна; после прохождения приложение передаёт одноразовый токен в Supabase Auth (`options.captchaToken`), а Supabase проверяет его своим секретным ключом. Обычно проверка проходит сама за секунду, галочку Cloudflare просит, только если не уверен.

## Что в коде (20.10.2026)

- `web/lib/captcha.tsx`: хук `useCaptcha()` (токен, `ready`, `reset()`), компонент `<CaptchaBox>` (сам виджет, скрипт Cloudflare подгружается только на этих экранах), `isCaptchaError()`, `CAPTCHA_ENABLED`. Токен одноразовый: после каждого запроса к Supabase виджет просит новый.
- Стоит в `SignInStep` (вход), `AccountStep` (регистрация), `ForgotPasswordFlow` («Забыли пароль») и `OtpCodeStep` (повторная отправка кода для регистрации и сброса). Ошибка проверки показывается текстом «Не удалось пройти проверку «Я не робот»…» (`onb.captchaFailed` на ru/en/ka).
- Без `NEXT_PUBLIC_TURNSTILE_SITE_KEY` виджет не рисуется и токен не посылается: приложение работает как раньше, пока капча в Supabase выключена.
- **Не затронуто:** вход через Telegram (сервер создаёт сессию через admin API, `app/api/auth/telegram/route.ts`), проверка кода из письма (`verifyOtp`), привязка почты (`updateUser`). Капча к ним не применяется.

## Как включить (порядок важен)

1. Cloudflare → Turnstile → Add widget: домен `catchrange.com` (для проверки на своём компьютере ещё `localhost`), режим Managed. Получить **Site key** и **Secret key**.
2. Vercel → проект `web` → Settings → Environment Variables: `NEXT_PUBLIC_TURNSTILE_SITE_KEY` = Site key (Production и Preview), затем Redeploy.
3. Только после того, как сборка с ключом вышла: Supabase → Authentication → Attack Protection (в новых версиях панели — Authentication → Settings) → включить CAPTCHA, провайдер Cloudflare Turnstile, вставить Secret key.

Если включить капчу в Supabase раньше, чем выйдет сборка с ключом, вход и регистрация перестанут работать (Supabase будет отказывать запросам без токена). Откат: выключить CAPTCHA в Supabase, это мгновенно.

## Проверка

Cloudflare даёт тестовые ключи: Site key `1x00000000000000000000BB` (невидимая, всегда пропускает), `3x00000000000000000000FF` (всегда просит галочку). Проверено на локальной странице: виджет загружается, два вызова подряд дают два токена.

## Как сделано 20.10.2026

Cloudflare: виджет «RANGE» (Managed) на `catchrange.com`. Vercel: `NEXT_PUBLIC_TURNSTILE_SITE_KEY` (публичный ключ). Supabase: CAPTCHA включена, провайдер Turnstile, секретный ключ вставлен владельцем. Запрос входа без токена и с фальшивым токеном Supabase отклоняет (`captcha_failed`).

## Вид

Над кнопкой стоит своя плашка в стиле приложения (`<CaptchaBox>` в `web/lib/captcha.tsx`, стили `.captcha-plate` в `globals.css`): шестиугольник, как у сектора. Пока идёт проверка, он пульсирует («Проверяем, что ты человек…»); когда проверка пройдена, заливается зелёным с галочкой («Проверка пройдена», плашка зеленеет); если не вышло, он красный с кнопкой «Повторить». Сама проверка Cloudflare работает за плашкой в режиме `interaction-only`. Когда Cloudflare не уверен, наша плашка уступает место его собственной галочке («Подтвердите, что вы человек», плоская, на всю ширину полей): на этот момент показывается только она. После нажатия галочка прячется, и остаётся наша плашка «Проверка пройдена». В остальных случаях игрок видит только нашу плашку. Рамку и шрифт галочки Cloudflare изменить нельзя (чужое окно). Накрыть её нашей плашкой так, чтобы нажатие проходило насквозь, не делали: Cloudflare не рекомендует скрывать или перекрывать виджет, и проверка может перестать срабатывать.

Решение владельца 20.10: сначала была невидимая проверка (не заметили), затем голый виджет Cloudflare (не нравился вид), затем своя плашка.
