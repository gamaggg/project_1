# Блокировка пользователя

`profiles.is_blocked` (`boolean not null default false`), публично читаема, как `is_admin`/`bio`. RPC `admin_set_blocked(p_user_id, p_blocked)` — `SECURITY DEFINER`, проверяет `is_admin` вызывающего, плюс два защитных guard'а: нельзя заблокировать самого себя и нельзя заблокировать другого админа (оба — явные `raise exception`, проверено вживую прямым вызовом RPC). Реальный эффект блокировки — не бан на уровне Supabase Auth (это требует service-role Admin API, недоступного клиентской `SECURITY DEFINER`-функции на анон-ключе), а отказ в `confirm_catch`: `if exists(... is_blocked) then raise exception 'account blocked'` в самом начале функции, до всех остальных проверок — заблокированный пользователь не может зафиксировать новый улов/захватить территорию, но по-прежнему может входить и просматривать приложение.

Кнопка «Заблокировать»/«Разблокировать» — в `UserProfileScreen.tsx`, рядом с кнопкой подписки, видна только при `useIsAdmin()` (`useSetBlocked()` → RPC). Бейдж «Заблокирован» рядом с именем показывается всем посетителям профиля, не только админу — как и с `is_admin`, публичность статуса не даёт никаких прав через клиент, а сокрытие бейджа только запутало бы обычных пользователей, почему у кого-то вдруг перестали появляться новые уловы.
