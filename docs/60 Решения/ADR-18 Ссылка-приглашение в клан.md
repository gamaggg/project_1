# Ссылка-приглашение в клан

**Решение: код приглашения — отдельная закрытая таблица, а не ref в ссылке**
Проще было бы считать приглашением `ref` ссылки, то есть публичный ID отправителя-старейшины. Но публичный ID виден в любом профиле: кто угодно собрал бы ссылку сам, и «только по приглашению» ничего бы не значило. Поэтому у клана есть секретный код (`clan_invite_codes`, RLS без политик). Его выдаёт только `get_clan_invite_code` и только старейшине и выше (то же правило, что у `invite_to_clan`), остальным возвращается null. `join_clan(p_clan_id, p_invite_code default null)` считает верный код приглашением: пропускает тип вступления и минимум секторов. Суточная пауза и лимит мест действуют как обычно. Код хранится не в `clans`, потому что `clans` читается кем угодно, со всеми колонками.

Клиент шлёт `p_invite_code` только когда код есть. Так обычное вступление остаётся тем же вызовом, что у опубликованной версии, и порядок выкладки клиента и миграции не важен. Код для кнопки «Поделиться» запрашивается заранее (`useClanInviteCode`): запись в буфер обмена в Safari должна происходить прямо в нажатии, без запроса между нажатием и записью. Сбросить код пока нельзя: если ссылка утечёт, главе придётся менять тип вступления. Кнопку «Сбросить ссылку» можно добавить позже.
