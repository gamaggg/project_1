# Аккаунты в Telegram Mini App

**Решение: мини-приложение создаёт аккаунт только по явному «начать»; вход по почте внутри Telegram забирает Telegram себе**
Раньше `/api/auth/telegram` создавал аккаунт всем, кто открыл мини-приложение без входа. Кто уже играл на сайте, получал второй, пустой аккаунт, и его Telegram привязывался к пустому. Так случилось с Русланом, и таких аккаунтов десятки. Теперь при запуске клиент передаёт `create:false`: вход выполняется только в существующий привязанный аккаунт. Создаёт аккаунт кнопка приветствия (`signInWithTelegram` → `create:true`). Клиенты без флага (старые версии) по-прежнему создают аккаунт.

После входа с почтой внутри Telegram (`INITIAL_SESSION`/`SIGNED_IN`, адрес не `@telegram.catchrange.com`) клиент вызывает `/api/auth/telegram/link` с токеном сессии и `initData`. Сервер проверяет обе стороны и ставит `telegram_id` этому аккаунту. Если `telegram_id` занят пустым автоаккаунтом (`isEmptyTelegramAccount`: служебный адрес, 0 уловов, нет клана), привязка переносится. Бот (`/start link_…`) делает то же самое.

Вход (`/api/auth/telegram`) выпускает токен на настоящий адрес аккаунта, к которому привязан `telegram_id`. Раньше токен шёл на служебный адрес, и владельцев аккаунтов с почтой заносило в чужой пустой аккаунт.

Пустые автоаккаунты после переноса остаются в базе без `telegram_id`, войти в них больше нельзя. Удалить их может супер-админ, автоматически это не делается.
