# Скорость запуска: параллельные страницы секторов и ленивые редкие экраны

**Решение: `useTerritories` не ждёт ни геометрию, ни проверку входа на сервере**
Геометрия (`sectors.json`) нужна только при склейке со строками базы, поэтому оба запроса идут одновременно: `ensureQueryData` берёт геометрию из того же кэша, что и `useSectorsGeometry`. Сами страницы `territories_with_stats` запрашиваются сразу обе (`TERRITORY_PARALLEL_PAGES = 2`, в базе ~1,9 тыс. строк), остальные — последовательно, если таблица вырастет. Порядок `order('id')` обязателен, иначе страницы пересекаются (см. CHANGELOG, баг от 27.09).

Запрос включается по `sessionReady`: это первое событие `onAuthStateChange`, сохранённая сессия уже прочитана. `loading` для этого не подходит: он ждёт ещё и сетевой `getUser()`, а это до 2,6 с в замерах. Раньше лишнюю загрузку с ключом «без пользователя» случайно предотвращало ожидание геометрии.

**Решение: редкие экраны — через свой `lazyComponent`, а не `next/dynamic`**
Нужно было, чтобы после предзагрузки экран рисовался в том же кадре, без Suspense и пустого мгновения. Поэтому `lazyComponent` запоминает загруженный компонент и рендерит его напрямую. Экземпляр, смонтированный до загрузки, остаётся в обёртке `React.lazy` на всю жизнь, чтобы не пересоздаться и не потерять введённое. Предзагрузка идёт по одному куску после `territoriesReady` в `requestIdleCallback`. Админские куски грузятся только при `isAdmin`/`isSuperAdmin`.

Отказ загрузки не кэшируется: `React.lazy` запомнил бы его навсегда. Вместо этого выполняются два повтора, затем показывается экран «Обновить». В ленивый список попадает только то, что открывают в меньшинстве сессий. Карта, сектор, рейтинг, активность, профиль, камера и подтверждение улова остаются обычными импортами. Онбординг и гостевой экран тоже: это первый экран для своих пользователей, и лишний запрос на старте его бы задержал.
