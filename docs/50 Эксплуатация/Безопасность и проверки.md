# Безопасность и проверки

Разбор 26.10.2026 (см. [[Аудит и план продвижения 2026-10-24|аудит]]): что проверено, что закрыто, какие правила держать при новых правках.

## Правила для новых функций базы
- **Права вызова.** У функции, созданной в Postgres, по умолчанию есть `EXECUTE` у `PUBLIC`, то есть у анонимов с публичным ключом сайта. Новая RPC: `revoke execute … from public, anon`, дальше `grant execute … to authenticated`, если её зовёт клиент. Внутренние функции (для cron и триггеров) закрыты у всех, кроме `postgres` и `service_role`.
- **Проверка внутри.** Админские функции проверяют `is_super_admin` или права в теле; игровые берут пользователя из `auth.uid()`, а не из параметра.
- **Никаких вставок «на лету».** `confirm_catch` не создаёт сектора: сектор должен существовать (до 26.10 функция создавала пустой сектор с любым названием, это закрыто миграцией `02`).
- **Адрес фото** в улове обязан лежать в папке самого игрока (`catch-photos/<uid>/…`).

## Маршруты `/api`
- Cron-маршруты (`/api/telegram/*`) проверяют секрет через `lib/cronAuth.ts` (пустой секрет отказывает всем, сравнение за постоянное время).
- `/api/recognize-fish` отвечает только вошедшим (токен в заголовке).
- Вход через Telegram: подпись `initData` проверяется по алгоритму Telegram, окно 24 часа (`lib/telegram/verifyInitData.ts`), токен входа выдаётся только на существующий или только что созданный аккаунт.
- Остаются открытыми по замыслу: `catch-conditions` (один запрос на улов), картинки `jackpot-card`, `story`, `recap` (их нагрузка видна в Vercel).

## Проверено и в порядке
Таблицы с включённой защитой строк, права на колонки `profiles` (нельзя менять `is_admin`, `coins` и подобное), политики записи, хранилище (загрузка только в свою папку), `.env` не в git, ключей в истории git нет, `npm audit` без уязвимостей (Next.js 16.4.3).

## Миграции безопасности (черновики в `web/supabase-drafts/security-26-10/`)
`01` права функций, `02` `confirm_catch`, `03` пределы файлов в корзинах, `04` лимит `log_app_events`. Состояние применения смотреть в [[Журнал изменений]].

## Что осталось
- Включить в Supabase Auth проверку утёкших паролей (может требовать платный тариф).
- Два представления (`profiles_with_stats`, `territories_with_stats`) работают с правами создателя намеренно (личные поля они скрывают для чужих строк); решение записать в ADR.
- Секрет cron лежит в тексте заданий `cron.job` (видно только владельцу базы); при желании заменить и перезапустить задания.
- Фиксация улова проверяет расстояние до сектора только на устройстве: прямой вызов RPC позволяет занять любой сектор. Серверная проверка координат нужна, но обходится подменой координат; решать вместе с механикой.
- Content-Security-Policy не включена (Mapbox, Telegram, Turnstile, аналитика; риск сломать приложение).

## Проверки перед «готово»
`npm run typecheck`, `npm run lint`, `npm test` (22 теста: парность переводов, ссылки-приглашения, расчёты кланов, cron-секрет, тексты публичных страниц), `npm run build`, после миграций `npm run db:contract`. То же гоняет GitHub Actions (`.github/workflows/ci.yml`).
