# Резервные копии базы

Бесплатный тариф Supabase своих бэкапов не делает, поэтому каждую ночь в 00:30 UTC (03:30 по Москве, 04:30 по Батуми) GitHub Actions снимает копию базы: `.github/workflows/db-backup.yml`.
- **Что входит.** Три файла по инструкции Supabase: `roles.sql`, `schema.sql`, `data.sql`. В них вся база, включая аккаунты (`auth.users`). Фото и аватары из Storage не входят.
- **Шифрование.** Репозиторий публичный, а артефакты и логи публичного репозитория может скачать любой пользователь GitHub. Поэтому файлы упаковываются и шифруются паролем (gpg, AES-256), и только потом сохраняются как артефакт `range-db-ГГГГ-ММ-ДД-ЧЧММ`. Хранится 30 дней. В логе только размеры файлов и число строк в главных таблицах.
- **Самопроверка.** Задача падает, если в дампе нет уловов или аккаунтов, или если зашифрованный файл не открывается тем же паролем. GitHub пишет владельцу репозитория на почту о каждом упавшем запуске.
- **Секреты репозитория** (GitHub → Settings → Secrets and variables → Actions):
  - `SUPABASE_DB_URL` — строка подключения Session pooler из Supabase (кнопка Connect → Session pooler) с паролем базы. Прямое подключение не подойдёт: оно только по IPv6, а машины GitHub его не поддерживают. Сброс пароля базы приложению не мешает: оно ходит по ключам API, `db:contract` тоже.
  - `BACKUP_PASSPHRASE` — пароль шифрования, не короче 20 символов (например, `openssl rand -base64 32`). Его нужно хранить ещё и у себя: GitHub секрет обратно не показывает, а без пароля копии не открыть.
- **Ручной запуск.** GitHub → Actions → Database backup → Run workflow.
- **GitHub отключает расписание** в публичном репозитории после 60 дней без коммитов. Тогда задачу нужно включить заново на той же странице.

**Как восстановить:**
1. GitHub → Actions → Database backup → нужный запуск → скачать артефакт (zip с файлом `.tar.gz.gpg`).
2. `gpg -d range-db-….tar.gz.gpg | tar xz` — спросит пароль шифрования, рядом появятся `roles.sql`, `schema.sql`, `data.sql`.
3. Восстановить в новый проект Supabase (или в пустой проект для частичного восстановления):
   ```bash
   psql --single-transaction --variable ON_ERROR_STOP=1 --file roles.sql --file schema.sql --command 'SET session_replication_role = replica' --file data.sql --dbname "<строка подключения нового проекта>"
   ```
   Для частичного восстановления (например, вернуть удалённые уловы) копию поднимают в отдельный проект и переносят оттуда нужные строки. Боевую базу целиком поверх не заливают.
